## Доставлено

Эмулятор передаёт сериализованный JSON в общий ReceiveWsMessage: id сообщения, departmentId, date, event в исходном формате. Интервал по умолчанию10сек, настройки1…300 целых секунд, пауза/возобновление, предел генерации100 (настраивается1…1000). Один recursive timeout и его версия предотвращают умножение таймеров; reset-version отменяет устаревшие загрузки. Предел останавливает генерацию без удаления задач. Настройки, счётчик и до2000 квитанций сохраняются в storage v1; старый снимок без stream совместим.

Приём проверяет envelope, дату/подразделение, типы полей, длительность, модель/заказчика/описание, затем общий нормализатор. Дедупликация по message ID и task ID во всех контекстах, в том числе повторно после await. Повтор не перезаписывает назначение, историю или статус. Незнакомый контекст загружается отдельно; поздний ответ не меняет выбранный день. Снимок всегда ссылается на существующий контекст даже при смене выбора во время загрузки.

Новые задачи добавляются в состояние без полного applyData и отмены drag. DOM очереди обновляется после завершения dialog/drag или ухода фокуса с карточки, прокрутка восстанавливается. Ввод/фокус в формах не меняются. Итоговый drop использует актуальное состояние и общий валидатор. Системные уведомления не сдвигают геометрию во время жеста. На широком экране свёрнутые настройки потока расположены рядом с индикатором.

Тестовые средства изолированы: при mockStorage=memory показана форма передачи JSON; mockWsOnDrag=once в этом режиме однократно доставляет сообщение на первом активном pointermove через тот же receiveWsMessage. В обычном UI диагностика скрыта. Настоящий WebSocket-сервер не добавлялся — используется согласованная эмуляция.
