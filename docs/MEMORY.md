## Принятые границы

- Один HTML, один CSS, один JS; без прикладных фреймворков. Только русский язык и светлая сине-зелёная тема, fluid-дизайн.
- Исходные модели PDF сохраняются; отдельный список `tasks` добавляет статусы и назначение. Все данные mock, реальные 1С/API/WS и авторизация вне текущей версии.
- Шаг назначения 15 минут, минимальный промежуток 30 минут, конфигурируемый обед запрещает любые события. Компетенции, отсутствие и `permitted` обязательны.
- Назначение/обратный перенос, ручные события, localStorage, сброс демо, WS-эмуляция по умолчанию каждые 10 секунд.
- Статусы меняются явными действиями. Отложить — в очередь; завтра — сохранить специалиста/время, конфликт отклонить; досрочное завершение сокращает занятость и сдвигает начало 30-минутного промежутка к факту.
- После каждого implementation TODO: независимое ревью → исправления/ревью → применимые проверки → живые сценарии Playwright в Google Chrome и/или Computer Use → актуальные результаты. Frontend unit-тесты и автоматические сканеры не добавляются.
- Основные сценарии и вёрстку проверяет исполнитель. Недоступные проверки — SKIPPED_ENVIRONMENT; существенное непроверенное поведение остаётся открытым.
- Git-записи принадлежат владельцу. Исходный PDF — существующий пользовательский файл, не изменять. Исторические разрешения CRW не переносятся на GMT Board.
