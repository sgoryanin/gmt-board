# ГМТ Доска

Демонстрационный календарь обращений: специалисты расположены по вертикали, время выбранного дня — по горизонтали, неназначенные обращения — в очереди. Интерфейс на русском языке, светлая тема, адаптивная вёрстка.

Приложение написано на **HTML, CSS и JavaScript без фреймворков**. В текущей версии нет CDN-зависимостей, установки npm-пакетов и этапа сборки. Все прикладные данные демонстрационные; сервер ниже только раздаёт файлы. Реального HTTP API, WebSocket-сервера, базы данных и серверной авторизации пока нет.

## Быстрый запуск

### Требования

- Python 3 для простого локального веб-сервера. Приложение не использует Python как backend: подойдёт и другой статический HTTP-сервер.
- Современный браузер с поддержкой `dialog`, Pointer Events, `structuredClone`, `crypto.randomUUID`, `AbortController` и `localStorage`. Для работы рекомендуем Google Chrome.
- Три файла `index.html`, `styles.css`, `app.js` в одной папке.

Проверка наличия Python на macOS/Linux:

```sh
python3 --version
```

### macOS и Linux

Откройте терминал и перейдите в корень проекта. Для текущего расположения репозитория:

```sh
cd /Users/sergei/Projects/Personal/gmt-board
python3 -m http.server 8765 --bind 127.0.0.1
```

На другом компьютере замените путь после `cd` на путь к своей папке проекта. Команда запускает сервер в текущем терминале. Дождитесь сообщения о прослушивании порта, затем откройте:

**[http://127.0.0.1:8765/](http://127.0.0.1:8765/)**

Оставьте терминал открытым на время работы. Для остановки этого сервера нажмите **Ctrl+C в том же терминале**. Для повторного запуска выполните ту же команду.

### Windows, PowerShell

Пример для проекта в `C:\Projects\gmt-board`:

```powershell
Set-Location 'C:\Projects\gmt-board'
py -3 -m http.server 8765 --bind 127.0.0.1
```

Если установлен Python без команды `py`, используйте:

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

Адрес в браузере и остановка через Ctrl+C такие же, как выше.

### Если порт 8765 занят

Если на нём уже работает это приложение, достаточно открыть его адрес. Если порт занят другим процессом, запустите свой сервер на свободном порту, например:

```sh
python3 -m http.server 8766 --bind 127.0.0.1
```

Откройте [http://127.0.0.1:8766/](http://127.0.0.1:8766/). Другой порт создаёт отдельное хранилище браузера: сохранённое демо с порта 8765 там не появится.

Привязка к `127.0.0.1` предназначена для работы на этом компьютере. `http.server` раздаёт содержимое выбранной папки и подходит для локального демо; он не реализует прикладной API или контроль доступа.

### Запуск на другом статическом сервере

Разместите `index.html`, `styles.css` и `app.js` рядом и откройте `index.html` через HTTP(S). Пути к CSS и JS относительные. Сборка, переменные окружения, `.env` и серверный роутинг не нужны. Markdown-документы и PDF не требуются для работы интерфейса.

Рекомендуемый способ запуска — HTTP по loopback-адресу либо HTTPS. Открытие двойным щелчком через `file://` не является основным проверенным сценарием: доступность браузерных API и поведение хранилища могут отличаться. При размещении на другом хосте используйте HTTPS для API безопасного контекста, включая генерацию UUID.

## Как пользоваться

1. Выберите подразделение и дату. В будние дни исходный календарь заполнен mock-задачами. «Региональная служба · просмотр» доступна только для чтения.
2. Выберите обращение в очереди. На широком экране с мышью перетащите его на строку специалиста либо откройте карточку и задайте специалиста и время через форму. На узком экране очередь открывается отдельной панелью; используйте форму назначения.
3. Приложение проверит компетенции, отсутствие специалиста, рабочее время, обед и промежуток между задачами. Начало назначения выбирается с шагом 15 минут; минимальный промежуток — 30 минут. Ошибка не изменяет расписание.
4. Откройте назначенную задачу, чтобы перенести её, вернуть в очередь, начать работу, отложить, завершить или перенести на завтра. Завтра — следующий календарный день: специалист и время сохраняются, конфликт отклоняет перенос.
5. Нажмите «Создать событие», выберите тип, описание и длительность в минутах. Событие сначала появится в очереди; его нужно назначить отдельно.
6. В панели потока изменяйте интервал и предел входящих обращений, ставьте поток на паузу и возобновляйте его. По умолчанию новая задача появляется каждые 10 секунд, до 100 принятых генератором сообщений.

Статус меняется явным действием. Наступление времени начала само по себе не переводит задачу в работу: меняются временные подсказки. Эскалация — отдельный признак обращения, не статус. Подробные правила — в [контрактах данных](docs/data-contracts.md).

## Сохранение и отдельное демо для экспериментов

В обычном режиме приложение сохраняет контексты дат и подразделений, задачи, назначения, статусы, историю и настройки потока в `localStorage` под ключом `gmt-board.demo.v1`. Перезагрузка страницы восстанавливает демо. Это локальные данные конкретного браузера и origin; `localhost`, `127.0.0.1`, разные порты и профили браузера имеют разные хранилища. Синхронизации между вкладками и пользователями нет.

Для экспериментов откройте **[отдельное демо в памяти](http://127.0.0.1:8765/?mockStorage=memory)**. Оно не читает и не меняет обычное сохранённое демо, но теряет свои изменения после перезагрузки. Для воспроизводимых сценариев можно также [зафиксировать часы на 2 ноября 2026 года, 09:37](http://127.0.0.1:8765/?mockStorage=memory&mockNow=2026-11-02T09:37).

«Сбросить демо» с подтверждением удаляет сохранение этого приложения в текущем режиме и создаёт исходные данные заново. Пользовательские события, назначения, история и счётчик потока сбрасываются. Используйте отдельное демо в памяти, если нужно сохранить рабочий пример.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Браузер не открывает страницу | Сервер запущен, терминал не закрыт, адрес и порт совпадают с командой запуска |
| Список файлов или 404 вместо приложения | Сервер запущен из папки, где лежит `index.html`; проверьте адрес `/` |
| Нет стилей или поведения | `styles.css` и `app.js` лежат рядом с HTML и доступны; проверьте Console и Network в инструментах разработчика |
| После правки файлов видна старая версия | Перезагрузите страницу без использования кэша браузера. Для изменений mock-расписания учитывайте отдельно сохранённые данные — см. [конфигурацию](docs/configuration.md) |
| Не приходят новые задачи | Проверьте паузу, предел, успешность загрузки контекста. Во время открытого диалога, перетаскивания или фокуса карточки очереди её перерисовка может быть отложена |
| Нельзя назначить событие | Прочитайте причину в форме: права, выходной, компетенции, отсутствие, обед, границы рабочего дня или промежуток |
| Пустой календарь в выходной | Выберите будний день; исходные назначения для субботы и воскресенья не генерируются |
| «Только в памяти» | Хранилище недоступно, повреждено или запись не удалась. Работа продолжается без сохранения после reload; доступен сброс демо |
| В Network нет запросов к API и WS | Это ожидаемо: mock-функции выполняются внутри `app.js`; реальные запросы идут только за статическими файлами |
